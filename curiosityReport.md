# Curiosity Report: McDonald’s App Needed More Penetration Testing

I’m writing this report shortly after having finished up the twelfth deliverable: Penetration Testing. To be honest, I struggled quite a bit to find any interesting exploits, despite being fairly familiar with the code of the system. So I was super curious to learn more about how people find exploits on systems for which they don’t even have access to the code. I ended up hitting a gold mine when I found a bunch of conversation around this report: https://eaton-works.com/2024/12/19/mcdelivery-india-hack/

This report, written by a whitehat hacker, goes over the details and discovery process of several different exploits in the McDonald’s India application. This particular case was especially attention-grabbing to me because it was so similar to our Pizza app, even using JWT tokens. It also explored vulnerabilities that I have had to fix for apps at my current job.

The primary vulnerability that was used against this app was a “Broken Object Level Authorization”. The first example of this was the order tracking route. While this route did indeed check that the request had a JWT Auth token, it did not care who the Auth token belonged to. This meant that by simply getting the default guest token given out to anyone before they even signed in, you could track anyone else's order. All that you had to do was open the site, then type in the url mcdeliver.co.in/order-tracking/1/0/0, and you could see the order specified by those number parameters. This problem was exacerbated by the fact that these variables were assigned sequentially, instead of randomly. This means that 1 was the first order made, 2 was the second, and so on. Because of this, someone could easily iterate over the parameters and get all the orders.

The report goes on to describe the other similar exploits that the hacker used against the system. My personal favorite was when they submitted a PUT request to update the price of their cart to 1 cent, and it worked. This ended up inspiring me to take another look at the JWTpizza code, and I think that a similar exploit would work there to make an order with whatever price you want.

Overall I would say that the biggest thing I learned was to be very careful when making your backend routing. Developers should carefully consider what sort of authorization access should be needed to perform every request. They should also be very careful about what sorts of things are allowed to be parameters in the request and what needs to be calculated by the server.
